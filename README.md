**پیام قیمت‌ها پنج بخش دارد:** بازارهای جهانی و رمزارز، طلا و سکه، گواهی‌های سپرده بورس کالا، حباب گواهی‌ها، و ارزهای پرتقاضا.

**رنگ دایره کنار هر قیمت** به این ترتیب تعیین می‌شود:

1. **درصد تغییر روزانه منبع**، اگر صفر نباشد. همین درصد کنار قیمت هم نوشته می‌شود، پس رنگ و درصد همیشه هم‌جهت‌اند.
2. **تغییر یک ساعت اخیر**، مثل یک کندل یک‌ساعته.
3. **آخرین حرکت قیمت** در تاریخچه.
4. اگر هیچ‌کدام نبود: ⚪️

## بات چطور اجرا می‌شود

بات روی سرور همیشه‌روشن اجرا نمی‌شود. هر بار که باید پیامی برود، **GitHub Actions** یک بار برنامه را اجرا می‌کند. برنامه پیام را می‌فرستد و تمام می‌شود.

```
cron-job.org (هر نیم ساعت + ۲۳:۵۵)  ──►  GitHub API  ──►  workflow «Post prices»
GitHub cron (پشتیبان، نامنظم)       ─────────────────►        │
                                                              ▼
                                         python main.py --post prices|summary
                                                              │
                         ┌────────────────────────────────────┼─────────────────┐
                         ▼                                    ▼                 ▼
               خواندن data/ از شاخه bot-data      گرفتن قیمت‌ها و ارسال     ذخیره data/ در bot-data
```

- **cron-job.org** زمان‌بند اصلی است: سر هر نیم ساعت و ساعت ۲۳:۵۵ اجرای workflow را درخواست می‌کند.
- **زمان‌بند داخلی گیت‌هاب** فقط پشتیبان است. گیت‌هاب اجراهای زمان‌بندی‌شده را با تأخیر انجام می‌دهد یا جا می‌اندازد، پس اجرای پشتیبان فقط وقتی پیام می‌فرستد که ۴۵ دقیقه هیچ پیامی نرفته باشد.
- **جلوگیری از پیام تکراری:** اگر دو اجرا نزدیک هم باشند، پیام تکراری نمی‌رود. پیام قیمت حداقل ۲۰ دقیقه و خلاصه حداقل ۱۲ ساعت فاصله دارد.
- **حالت همیشه‌روشن:** اجرای `python main.py` بدون `--post`، بات را در این حالت راه می‌اندازد. در این حالت بخش تعاملی بات (`/start`، چک عضویت کانال، `/prices`) هم کار می‌کند، ولی فعلاً از آن استفاده نمی‌شود. اگر روزی بات را روی یک سرور اجرا کردید، cron-job.org و GitHub Actions را خاموش کنید تا پیام‌ها دوبار نروند.

## مسیر یک پیام قیمت، از اول تا آخر

1. **راه‌اندازی:** cron-job.org درخواست اجرای workflow را با `kind=prices` می‌فرستد.
2. **بازیابی داده‌ها:** workflow کد را دریافت می‌کند، پکیج‌ها را نصب می‌کند، و شاخه `bot-data` را در پوشه `data/` باز می‌کند تا داده‌های اجراهای قبلی در دسترس باشند.
3. **چک تکراری:** `python main.py --post prices` اجرا می‌شود. `post_once` در `main.py` اول نگاه می‌کند پیام اخیر رفته یا نه؛ اگر رفته، بدون کاری تمام می‌شود.
4. **گرفتن قیمت‌ها:** `post_prices` تابع `get_quotes` را از `price_service.py` صدا می‌زند. این تابع:
   - برای هر قیمت در `ASSET_GROUPS`، تابع منبعش را همزمان اجرا می‌کند. قیمت‌هایی که بازارشان بسته است، مثل تتر بعد از ساعت ۲۱، کنار گذاشته می‌شوند.
   - هر قیمتی که خطا بدهد فقط از پیام حذف می‌شود و علتش در `fetch_failures` ثبت می‌شود.
   - قیمت‌ها را با قیمت یک ساعت قبل از `history.py` جفت می‌کند و قیمت‌های جدید را به تاریخچه اضافه می‌کند.
5. **هشدار:** `alerts.check_missing_prices` قیمت‌هایی که حذف شده‌اند را بررسی می‌کند و اگر لازم باشد به ادمین هشدار می‌دهد.
6. **ساخت متن:** `format_price_message` در `formatter.py` متن پیام را می‌سازد و `bubbles.py` بخش حباب را حساب می‌کند.
7. **ارسال یا ویرایش:** پیام جدید فرستاده می‌شود، یا (خارج از ۹ تا ۱۸، در نیم ساعت) پیام ساعت قبل ویرایش می‌شود.
8. **ذخیره داده‌ها:** آخرین مرحله workflow، تغییرات پوشه `data/` را در شاخه `bot-data` ذخیره می‌کند.

## داده‌های ذخیره‌شده

همه این فایل‌ها در شاخه **`bot-data`** ریپو هستند، نه `main`. روی سیستم خودتان در پوشه `data/` ساخته می‌شوند که git آن را نادیده می‌گیرد.

| فایل | محتوا |
|---|---|
| `history.json` | قیمت‌های ۲۶ ساعت اخیر با زمانشان، برای کندل یک‌ساعته و آخرین حرکت |
| `last_post.json` | قیمت‌های آخرین پیام. خلاصه شبانه برای قیمت‌هایی که آن لحظه بسته‌اند از این استفاده می‌کند. |
| `last_summary.json` / `last_weekly_summary.json` | قیمت‌های آخرین خلاصه روزانه و هفتگی؛ درصدهای خلاصه بعدی نسبت به این‌ها حساب می‌شوند |
| `post_times.json` | زمان آخرین ارسال هر نوع پیام، برای جلوگیری از پیام تکراری |
| `message_ids.json` | شماره آخرین پیام قیمت، برای ویرایش آن در نیم ساعت |
| `pinned.json` | شماره خلاصه پین‌شده، برای برداشتن پین آن در شب بعد |
| `alerts.json` | مشکلات فعلی و اینکه هشدارشان فرستاده شده یا نه |

اگر یکی از این فایل‌ها را پاک کنید، چیزی خراب نمی‌شود. فقط قابلیت مربوطه از صفر شروع می‌کند؛ مثلاً اولین خلاصه بعد از پاک کردن `last_summary.json` بدون درصد می‌آید.

## تنظیمات و Secret ها

| تنظیم | کجا | مقدار |
|---|---|---|
| `BOT_TOKEN` | **Secret** گیت‌هاب (و `.env` روی سیستم خودتان) | توکن بات از BotFather |
| `ADMIN_CHAT_ID` | **Secret** گیت‌هاب (اختیاری) | آیدی عددی تلگرام شما برای هشدارها |
| `CHANNEL_ID` | داخل workflow | `@PricePulseIR` |
| `CHANNEL_TITLE` | داخل workflow | اسم پایین پیام‌ها |
| `TIMEZONE` | پیش‌فرض `Asia/Tehran` | |

**Secret ها:** در `Settings ← Secrets and variables ← Actions` ریپو.

**فایل `.env`:** برای اجرا روی سیستم خودتان، `.env.example` را به اسم `.env` کپی کنید و پر کنید. این فایل هیچ‌وقت وارد git نمی‌شود.

**توکن گیت‌هاب در cron-job.org:** cron-job.org برای صدا زدن گیت‌هاب از یک توکن گیت‌هاب (Fine-grained) استفاده می‌کند که فقط به ریپوی `pricepulse` و با دسترسی **Actions: Read and write** محدود است. این توکن تا ۱ اکتبر ۲۰۲۷ اعتبار دارد. بعد از آن باید توکن جدید بسازید و در هر دو cronjob جایگزین کنید.

## تغییرات رایج: کجا را عوض کنم؟

### اضافه کردن یک قیمت جدید

همه‌چیز در `ASSET_GROUPS` در [`assets.py`](assets.py) است. هر خط یک قیمت است و ترتیب خط‌ها همان ترتیب داخل پیام است. هر گروه یک بلوک پیام است و بین گروه‌ها یک خط خالی می‌آید.

</div>

```python
Asset("cny", "یوان چین", "CNY", "تومان", _tgju_toman("price_cny")),
#      │       │           │       │       └─ منبع: کلید tgju (قیمت ریالی، تبدیل به تومان)
#      │       │           │       └─ واحد داخل پیام. اگر با «دلار» شروع شود، در خلاصه با $ نوشته می‌شود
#      │       │           └─ اسم کوتاه داخل خلاصه شبانه
#      │       └─ اسم داخل پیام قیمت
#      └─ کلید ثابت. برای ذخیره قیمت‌های قبلی استفاده می‌شود؛ بعداً عوضش نکنید
```

<div dir="rtl">

بقیه گزینه‌ها:

- `decimals=2`: تعداد اعشار نمایش داده‌شده. پیش‌فرض صفر است.
- `trading_hours=(time(9, 0), time(21, 0))`: بیرون این ساعت‌ها قیمت در پیام نمی‌آید (مثل تتر).
- `_tgju("key")`: برای قیمت‌های جهانی دلاری tgju، که تبدیل به تومان نمی‌شوند.
- `_ime("key", "اسم", "Symbol", "TICKER")`: برای یک گواهی سپرده دیگر از chartix.

**پیدا کردن کلید یک قیمت در tgju:** این دستور همه کلیدهایی را که کلمه داده‌شده در اسمشان هست، همراه با قیمت و زمان آخرین به‌روزرسانی، نشان می‌دهد. کلیدی را انتخاب کنید که `ts` آن امروز باشد:

</div>

```bash
curl -s https://call4.tgju.org/ajax.json | python -c "import json,sys; c=json.load(sys.stdin)['current']; [print(k, v['p'], v['ts']) for k,v in c.items() if 'cny' in k]"
```

<div dir="rtl">

### حذف یا جابه‌جایی یک قیمت

خطش را در `assets.py` پاک کنید یا جابه‌جا کنید.

### تغییر ساعت‌های ارسال

- **ساعت‌های شلوغ بازار** (پیام جدید هر نیم ساعت): `BUSY_HOURS` در `main.py`.
- **ساعت خلاصه یا روز خلاصه هفتگی:** زمان cronjob در **cron-job.org**، به‌علاوه `DAILY_SUMMARY_TIME` و `WEEKLY_SUMMARY_WEEKDAY` در `main.py`.
- **زمان‌بند پشتیبان گیت‌هاب:** خطوط `cron:` در workflow. این ساعت‌ها به وقت **UTC** هستند (تهران = UTC+3:30).

### تغییر ظاهر پیام

همه در [`formatter.py`](formatter.py) است:

- **ایموجی‌ها و عنوان‌ها:** ثابت‌های اول فایل (`UP`، `DOWN`، `CHANNEL_EMOJI`، `SUMMARY_TITLE` و غیره).
- **شکل هر خط:** `format_quote` (پیام قیمت)، `format_summary_quote` (خلاصه)، `format_bubble` (حباب).
- **پایین پیام** (تاریخ، اسم و آیدی کانال): `_footer`.

**نکته خطوط فارسی:** خطوط فارسی با `rtl_line` بین دو کاراکتر نامرئی راست‌به‌چپ قرار می‌گیرند، چون بدون آن تلگرام بعضی خط‌ها را چپ‌به‌راست نشان می‌دهد. اگر خط جدیدی اضافه کردید، از همین تابع استفاده کنید.

### تغییر محاسبه حباب

در [`bubbles.py`](bubbles.py). وزن هر واحد گواهی طلا و نقره از توضیحات chartix گرفته شده (طلا ۰٫۱ گرم با عیار ۹۹۵، نقره ۱ گرم). وزن مس و روی (۱ کیلوگرم) **تأیید نشده** است.

### تغییر آستانه‌های هشدار

`MISSING_GRACE` و `NO_POST_LIMIT` در [`alerts.py`](alerts.py).

```bash
python -c "import asyncio, price_service, formatter; print(formatter.format_summary_message(asyncio.run(price_service.get_summary_quotes())))"
```

<div dir="rtl">

**این دستورها روی کانال اصلی پیام می‌فرستند؛ با احتیاط استفاده کنید:**

- `python main.py --post prices` و `python main.py --post summary`: یک بار ارسال می‌کنند.
- `python main.py`: بات را در حالت همیشه‌روشن اجرا می‌کند. اگر GitHub Actions هم فعال باشد، پیام‌ها دوبار ارسال می‌شوند.

**داده‌ها روی سیستم خودتان:** وقتی روی سیستم خودتان اجرا می‌کنید، داده‌ها در پوشه `data/` همین پروژه ذخیره می‌شوند، نه در شاخه `bot-data` گیت‌هاب.

**اعمال تغییرات روی کانال:** هر تغییری که در شاخه `main` گیت‌هاب push شود، از اجرای بعدی روی کانال اعمال می‌شود. قبل از push، حتماً پیش‌نمایش را ببینید.

**اجرای دستی روی گیت‌هاب:** تب **Actions** ← **Post prices** ← **Run workflow**. لاگ هر اجرا هم همان‌جا دیده می‌شود (مرحله **Post**).
